Website rework · proposal for discussion

51 Walden, off WordPress and pointed at 2026

A plan for rebuilding 51walden.org on a platform its volunteers can run without a developer on call — and for giving the site the same care the board has spent on the building: the Access 51 accessibility campaign, the new HVAC, four resident companies putting on 60+ performances a year for about 8,000 patrons. None of that is on the homepage today.

01 · where the site stands today

The building is in better shape than the front door

A walk through the live site turns up a WordPress build that's technically fine — it's responsive, it loads, the menus work — but the architecture buries the things a 2026 nonprofit visitor and a 2026 nonprofit board both expect to find fast.

Giving

"Donate" is labeled "Contribute" and sits three levels deep, inside the Contact menu. There's no giving button anywhere in the persistent header.

Trust signals

The Access 51 campaign raised $500k for ADA restrooms, a stage lift, and accessible restrooms — real, verifiable nonprofit credibility — but it's one paragraph on a "Facility" subpage no one lands on.

Impact

60+ performances and ~8,000 patrons a year is a strong number that exists only inside the PDF annual-appeal letter, not on the page a first-time visitor sees.

Venue rental

No path to inquire about renting the hall or dance studio. The Facility page describes a 350-seat space with two stages and stops there — no pricing, no availability, no form.

Resident groups

Concord Band, Concord Players, Concord Orchestra, and Opera51 each get a short paragraph and a "Learn More" link off-site — the four organizations that are the venue's programming read as an afterthought.

Content sprawl

Events split across separate "Event Calendar" and "Past Events" pages, a standalone "Code of Conduct," a linked PDF for HVAC/air-quality details — reasonable content, scattered without a spine.

03 · platform

Move off WordPress — onto Squarespace

The explicit ask was an easier platform, run by volunteers, with no dedicated developer on staff. That rules out anything that still needs plugin updates, security patching, or a build step.

PlatformVolunteer upkeepBuilt-in giving & eventsDesign controlRough cost
WordPress (current)Plugin & core updates, security patching, a builder plugin (Divi-class) to maintainVia added plugins (more surface area)Highest, at a costHosting + plugin licenses, ~$200–500/yr
Squarespace RecommendedZero patching; one login; a non-technical volunteer can edit text and photos safelyNative Stripe donations, native events/calendar, native formsGood within templates; less freeform than Webflow~$25–49/mo, annual billing
WebflowNo patching, but the visual builder has a real learning curve for non-designersForms & CMS native; giving needs a Stripe/Donorbox embedHighest of the no-code options~$23–40/mo, plus more setup time
WixSimilarly low-maintenanceDonations via app; weaker content modeling for four repeating "resident group" pagesGood, less clean CMS structure~$27–49/mo

Squarespace wins on the criterion that matters most for an all-volunteer board: nobody has to think about hosting, updates, or plugin conflicts again. If a design-capable volunteer or a hired freelancer stays involved long-term, Webflow is the fallback — more visual range, at the cost of a steeper handoff.

05 · design direction

Look and feel

51 Walden's own materials already lean into it: comedy-and-tragedy masks in the current mark, a National Register building from 1887, four resident companies with their own decades of history. The redesign should read like a well-kept playbill for a historic house — not a generic template with an orange call-to-action button.

  • Photography-led, not stock-led. Real photos from the four resident groups' actual productions and rehearsals in the hall — a single coordinated half-day shoot covers the gap cheaply.
  • A quieter palette than the current blue-and-orange builder default: ink and pine greens (a nod to Walden's own woods and pond) with an aged-brass accent for calls to action, rather than a generic bright-orange button.
  • One consistent template for all four resident groups — same layout, same fields (season, rehearsal night, ticket link, short history) — so none of the four reads as more or less cared-for than the others.
  • The accessibility story told as a page, not a footnote — it's genuine capital-campaign work worth the same visual treatment as the "Up Next" event.
06 · roadmap

Five acts, about a season's worth of evenings and weekends

Sequenced so a volunteer committee can run it around existing rehearsal and performance schedules — and so cutover lands in a dark week between seasons, not mid-run.

IDiscovery
Weeks 1–3

Audit & content pull

  • Inventory every current page, PDF, and form (including the Airborne-Virus-Mitigation notice and Code of Conduct)
  • Export the existing email list before touching any WordPress plugin it depends on
  • Collect updated copy, rosters, and season info from each of the four resident groups
  • Pull real numbers already in hand: annual attendance, patron count, founding/residency dates
IIDesign
Weeks 3–6

Sitemap, wireframes, visual direction

  • Sign off the six-pillar sitemap with the board
  • Low-fidelity wireframes: homepage, resident-group template, rental page
  • Palette, type, and photography direction; one board review pass
IIIBuild
Weeks 6–10

Build in Squarespace

  • Build all pages against the approved wireframes
  • Connect Stripe for one-time and recurring donations
  • Set up the events calendar and the rental inquiry form
  • Wire the footer email signup to a newsletter tool
  • Map every current WordPress URL to its new address for redirects
IVLaunch
Weeks 10–12

QA, accessibility pass, cutover

  • Cross-device QA and a contrast/alt-text/focus-state pass
  • 301 redirects live before DNS points at the new site
  • Schedule the DNS cutover for a dark week between seasons
  • Resubmit the sitemap to Search Console; watch for 404s in week one
VHandoff
Ongoing

Keep it maintainable

  • A one-page editing guide, kept in the org's shared drive — not one person's inbox
  • A named site admin, reviewed each annual meeting alongside the board
  • A quarterly freshness check: current season, board roster, financial-transparency link
